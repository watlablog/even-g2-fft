# even-g2-fft

Even G2のマイクで録音し、平均化したFFT振幅スペクトルを表示するアプリの開発プロジェクトです。TypeScriptとEven Hub Web SDKを使用します。

現在は、録音の開始・停止、直近5秒の時間波形、録音終了後の平均化FFT、カーソルによる周波数・振幅の確認まで実装しています。シミュレーターではmacOSの内蔵マイクで検証済みです。G2実機でも初期画面、録音、録音終了後のFFT画像表示まで確認しています。

セットアップ済みの環境で再確認する場合は、[実機でのビルド・起動・動作確認](#実機でのビルド起動動作確認)の手順を順に実行してください。

メガネのメニューから起動するためのインストール手順は、[Beta版の作成・登録・インストール](#beta版の作成登録インストール)にまとめています。

## シミュレーターの起動と手動テスト

ビルド済みの画面を使う場合は、ターミナルを2つ開きます。

### ターミナル1：ビルドとプレビューサーバー

```bash
cd /path/to/even-g2-fft
npm run build
npm run preview -- --port 4173 --strictPort
```

サーバーを起動したままにします。`--strictPort` を指定しているため、4173番ポートが使用中の場合は既存のサーバーを終了してから再実行してください。

### ターミナル2：内蔵マイクを指定して起動

以下は、内蔵マイクのデバイスIDが `coreaudio:BuiltInMicrophoneDevice` の場合のコマンド例です。

```bash
cd /path/to/even-g2-fft
npx evenhub-simulator http://localhost:4173/ --aid "coreaudio:BuiltInMicrophoneDevice"
```

`--aid` の値は `--list-audio-input-devices` の結果に合わせて指定してください。macOSのマイク許可が表示された場合は「許可」を選択します。

### 操作

1. 初期画面に `FFT ready` と `Tap to record` が表示されます。
2. シミュレーターの `Click`（シングルタップ）操作で録音を開始します。
3. 選択したマイクに向かって「話す → 数秒黙る → また話す」と操作し、音の強い区間が右端から左へ移動することを確認します。
4. もう一度シングルタップすると録音区間が閉じ、停止時点の波形に `Calculating...` を重ねて解析します。メッセージは500 msごとに表示／非表示が切り替わり、解析後に全画面FFTへ移ります。計算が速い場合は点滅の切り替わり前に結果が表示されます。
5. 結果画面はNormal modeで表示されます。シングルタップで新しい録音を開始し、前の録音データをリセットします。カーソルを使う場合は、以下のメニュー操作でCursor modeへ切り替えます。
6. 128 ms未満の録音では短すぎる旨を表示します。シングルタップで録音し直せます。計算中と画面切替中のタップは無視します。

録音データはメモリ内に保持します。音声ファイルへの保存は実装していません。

### FFT画面のカーソル操作

FFT結果画面で「タップ→長押し」の標準メニューを開き、`Cursor mode` または `Normal mode` を選びます。シミュレーターではContext Menu操作でも開けます。

| 操作 | Normal mode | Cursor mode |
| --- | --- | --- |
| シングルタップ | 新しい録音を開始 | 何もしない |
| Upスクロール | 何もしない | 低周波側へ1ビン移動 |
| Downスクロール | 何もしない | 高周波側へ1ビン移動 |
| ダブルタップ | 何もしない | 表示範囲内の最大振幅位置へ戻す |
| 長押し | アプリ側での追加処理なし | Normal modeへ戻す |
| メニューのモード選択 | 選んだモードへ切替 | 選んだモードへ切替 |

- 1ビンは7.8125 Hzです。0〜3,000 Hzの端で止まり、反対側には移動しません。
- Cursor modeを選ぶたびに、表示範囲内の平均パワーが最大のビンへカーソルを配置します。同率なら低周波側、全無音なら0 Hzを選びます。
- カーソルは縦の破線です。グラフの右上に黒背景の数値欄を重ね、周波数と振幅を `1000.00 Hz` / `84.95 dB` のように小数点以下2桁で表示します。打ち切り値は `≤-120.00 dB` と表示します。
- モード切替とカーソル移動ではFFTを再計算せず、元の軸範囲を保持します。Normal modeではカーソルと数値欄を消し、元のグラフを復元します。
- メニュー表示中は背後の画面の入力と新しい画像転送の開始を抑止し、メニューが閉じてから選択したモードを描画します。長押しの解放では録音を開始しません。


コードを変更した場合は、再度 `npm run build` を実行し、シミュレーターを終了して起動し直してください。プレビューサーバーはビルド済みの `dist/` を配信します。

### 開発サーバーを使う場合

```bash
# ターミナル1
npm run dev
```

```bash
# ターミナル2（Viteが表示した実際のURLを指定）
npx evenhub-simulator http://localhost:5173/ --aid "coreaudio:BuiltInMicrophoneDevice"
```

開発中の自動リロードや実機のプロトタイプモードでのQR再読み取りでは、前のページがホストに残り、初期ページの再作成が結果コード `1` で拒否されることがあります。本アプリはSDK側のレイアウト検証後に初期ページを作成し、結果が `1` の場合だけ `rebuildPageContainer()` で一度復元を試みます。復元も失敗した場合はエラーを表示します。シミュレーターを終了して起動し直すか、実機ではプロトタイプモードを終了して再度起動してください。手動テストには上記のプレビューサーバーを使用できます。

実機診断では、短い名前のテキスト・画像コンテナは受理され、16文字の `recording-status` を含む構成は拒否されました。元のアプリで録音状態のコンテナ名だけを `status` に短縮したところ、正常起動と録音・FFT表示を確認できました。結果コード `1` は再作成時だけでなく画面設定の拒否でも返るため、復元に失敗する場合は設定も確認します。

## 実機でのビルド・起動・動作確認

この手順では、リポジトリのソースをビルドし、4173番ポートのプレビューサーバーからG2実機で動作確認します。調査に使った一時診断サーバーや診断ページを用意する必要はありません。

### 1. iPhoneとG2を準備する

1. G2をEven Realitiesアプリに接続し、メガネを装着します。
2. iPhoneとMacを同じWi-Fiに接続します。
3. [Even HubのWebサイト](https://hub.evenrealities.com/login)へスマホアプリと同じアカウントでログインします。
4. Evenアプリを完全に終了して開き直し、プロトタイプモードが表示されることを確認します。すでに表示されている場合は、そのまま使用できます。

### 2. リポジトリを確認する

Macでターミナルを2つ開きます。ターミナル1でリポジトリのルートへ移動します。

```bash
cd /path/to/even-g2-fft
git rev-parse --show-toplevel
git status --short
```

`/path/to/even-g2-fft` は実際の作業フォルダに置き換えてください。初期構築済みのソースと `app.json` を使います。

初回クローン後など、依存パッケージがまだ導入されていない場合は、先に次を実行します。`package-lock.json` に記録されたバージョンを導入します。

```bash
npm ci
```

### 3. ビルドして配信する（ターミナル1）

以前のプレビューサーバーが4173番ポートで動いている場合は、そのサーバーを起動したターミナルで `Ctrl+C` を押して終了してから、以下を実行します。

```bash
npm run build
npm run preview -- --host 0.0.0.0 --port 4173 --strictPort
```

ビルドがエラーなく終了し、プレビューサーバーの `Network:` にLAN向けURLが表示されれば、Mac側の準備は完了です。このターミナルはサーバーを起動したままにします。`--strictPort` は、4173番ポートが使用中の場合に別ポートへ自動で変わることを防ぎます。

### 4. LANアドレスを確認してQRを生成する（ターミナル2）

ターミナル2でも同じリポジトリへ移動し、MacのLANアドレスを変数に保存して表示します。

```bash
cd /path/to/even-g2-fft
mac_lan_ip="$(ipconfig getifaddr en0)"
echo "$mac_lan_ip"
```

`192.168.x.x` などのIPv4アドレスが出ることを確認します。空の場合は、次で別のインターフェースを確認してください。表示されたアドレスがターミナル1の `Network:` と一致することを確認してから進みます。

```bash
mac_lan_ip="$(ipconfig getifaddr en1)"
echo "$mac_lan_ip"
```

アドレスが確認できたら、同じターミナル2で次を実行します。

```bash
npx evenhub qr --url "http://${mac_lan_ip}:4173/" --external
```

QR画像が別ウィンドウで開きます。QRにはMacのLANアドレスを使います。`localhost` はiPhone自身を指すため、実機確認用のURLには使用できません。

### 5. アプリを開き、録音からFFTまで確認する

Evenアプリのプロトタイプモードで、手順4のQRを読み取ります。テスト中はiPhoneをロックせず、Evenアプリを前面に表示し、Macのプレビューサーバーを起動したままにします。

| 順番 | 操作 | 確認する表示・動作 |
| --- | --- | --- |
| 1 | QRを読み取る | メガネに `FFT ready` と `Tap to record`、時間波形の枠が表示される |
| 2 | メガネをシングルタップする | 録音が始まり、`Recording` と経過秒数が表示される |
| 3 | 「2秒話す → 3秒黙る → もう一度2秒話す」 | 波形が音に反応し、強い音の区間が右から左へ動く。横軸は0〜5と `Time[s]`、縦軸は−1〜+1 |
| 4 | もう一度シングルタップする | 録音が終了し、停止時点の時間波形を背景にFFT解析が行われる |
| 5 | FFT表示を待つ | 全画面のFFT画像へ切り替わり、`Frequency[Hz]`、0〜3,000 Hzの目盛り、`Amplitude` とdB表記が表示される |
| 6 | Normal modeのFFT画面でシングルタップする | 前回の記録がリセットされ、次の録音が始まる。再度タップしてFFTへ戻れる |

解析中の `Calculating...` は500 msごとに点滅します。解析が速い場合は、点滅を目視する前にFFT表示へ切り替わります。

今回の実機確認では初期表示、録音、FFT画像表示まで成功しています。波形の詳しい動きや再録音も含め、上の表で改めて確認できます。

### 6. カーソル・メニューを追加確認する

カーソル・標準メニュー・R1の実機確認は未完了です。追加で確認する場合は、FFT画面で「タップ→長押し」の標準メニューを開き、`Cursor mode` を選択します。[FFT画面のカーソル操作](#fft画面のカーソル操作)の表に沿って、スクロールによる移動、単位付き数値表示、ダブルタップで最大位置へ戻ること、Normal modeへの復帰を確認します。

### 7. コードを変更して再確認する場合

ターミナル1のサーバーを `Ctrl+C` で終了し、手順3のビルドと配信を再実行します。Evenアプリではプロトタイプモードを開き直してQRを読み取り、手順5から確認します。MacのLANアドレスが変わった場合は手順4でQRも生成し直します。

プレビューサーバーが配信するのは `dist/` のビルド結果です。ソースを編集した後は、再度 `npm run build` を実行してから読み取ってください。

### うまく動かない場合

| 症状 | 確認すること |
| --- | --- |
| `Port 4173 is already in use` | 以前のプレビューサーバーを起動したターミナルで終了し、手順3を再実行する |
| プロトタイプモードが表示されない | WebのEven Hubとスマホアプリが同じアカウントか確認し、Webログイン後にスマホアプリを完全に終了して開き直す |
| QR読み取り後、ロード中のまま | サーバーが起動中か、QRのLANアドレスとポートが正しいか、iPhoneとMacが同じWi-Fiかを確認する |
| iPhoneからMacへの到達を確認したい | ターミナル1の `Network:` のURLをiPhoneのSafariで開く。ページが表示されれば到達できている。メガネの表示・録音はEvenアプリから確認する |
| `Failed to create startup page: 1`、または作成・復元失敗 | G2が接続・装着済みか確認する。最新ソースの `textName` が `status` であることを確認して再ビルドする。改善しない場合はEvenアプリを完全に終了して開き直し、再度QRを読み取る |
| 編集前の画面が出る | ビルドが成功しているか、QRが手順3のサーバーを指しているかを確認し、QRを再読み取りする |
| 録音が短すぎる旨が出る | 128 ms以上の録音が必要。もう一度タップし、数秒録音してから停止する |

## Beta版の作成・登録・インストール

Beta版をインストールするとメガネのメニューから起動できます。Macの配信サーバーとQR読み取りは不要になりますが、アプリの処理は引き続きスマホのEvenアプリで動きます。以下は自分だけをテスターとして登録する手順です。

### 1. 配布設定を確認してパッケージを作る

現在の `app.json` は次の設定です。

| 項目 | 設定 |
| --- | --- |
| アプリ名 | `Even G2 FFT` |
| パッケージID | `com.watlablog.eveng2fft` |
| バージョン | `0.1.0` |
| SDK | `0.0.16` |
| 最低Evenアプリバージョン | `2.2.10`。SDK `0.0.16` のメタデータによるパッケージ作成時の確認値 |
| 権限 | `g2-microphone`。G2マイクで波形・FFT用の音声を録音 |
| 表示言語 | `en`。メガネの画面は英語表記 |

リポジトリのルートでビルドし、パッケージを作成します。

```bash
cd /path/to/even-g2-fft
npm run build
npx evenhub pack app.json dist --sdk-ver 0.0.16 -o even-g2-fft.ehpk
```

ルートに生成される `even-g2-fft.ehpk` がインストール用ファイルです。`--sdk-ver` はビルドに使ったSDKを指定し、CLIが最低アプリバージョンを判定するために使用します。パッケージは `.gitignore` で除外しています。

このローカルでのパッケージ作成には、Even Hubへのログインやスマホの操作は不要です。[公式のパッケージ作成手順](https://hub.evenrealities.com/docs/ship/packaging)

バージョン `0.1.0` のビルド、パッケージ作成、Betaへの配布指定、テスターの有効化、iPhoneへのインストールまで確認済みです。再実行する場合は、以下の手順に沿って進めます。

### 2. 初回のアプリ登録とアップロード

スマホのEvenアプリと同じアカウントでログインします。

```bash
npx evenhub login
npx evenhub create even-g2-fft.ehpk --name "Even G2 FFT" --tagline "Audio waveform and averaged FFT"
```

`create` は新しいアプリと最初のビルドを登録します。アイコン未指定時は仮アイコンになります。パッケージIDがほかのアプリに使われている場合は、利用可能なIDに変更してからパッケージを作り直します。[公式の初回登録手順](https://hub.evenrealities.com/docs/cli/apps)

### 3. 自分をBetaテスターとして招待する

メールアドレスを、スマホのEvenアプリで使っている自分のアドレスに置き換えて実行します。

```bash
npx evenhub testers add "your-email@example.com"
```

招待メールのリンクを開いて承諾した後、次のコマンドで状態が `Active` になったことを確認します。

```bash
npx evenhub testers
```

### 4. ビルドをBetaに切り替える

```bash
npx evenhub promote 0.1.0 --to beta
npx evenhub ls com.watlablog.eveng2fft
```

対象バージョンのチャンネルがBetaであることを確認します。CLIのJSON出力では、配布先を `channels` で確認します。`status` が `Private` でも、`channels` に `"beta"` が含まれていればBetaへの割り当ては完了しています。ポータルで操作する場合は、アプリのBuildsで対象ビルドの `Private` タグをクリックし、`Beta` を選んで `Promote to Beta` を確定します。

インストールには、ビルドが `Beta` であることと、テスターが `Active` であることの両方が必要です。「テスト版の期限切れ」と表示される場合も、この2つを確認します。[公式のBeta配布手順](https://hub.evenrealities.com/docs/test/beta-testing)

### 5. iPhoneへインストールしてメガネから起動する

1. iPhoneのEvenアプリで `Beta tester` を開きます。公式の案内は `Me → Beta tester` です。
2. `Even G2 FFT` を選び、`Install` を実行します。マイク権限が求められたら許可します。
3. G2が接続された状態で、メガネのメニューから `Even G2 FFT` を起動します。
4. Macのプレビューサーバーを終了した状態で、初期表示、録音、FFT画像表示を確認します。
5. アプリの終了と再起動、iPhoneをロックした後の動作も確認します。

Beta版のインストール、実際の権限確認、メガネのメニューからの起動は、プロトタイプモードとは別に実機で検証する項目です。

バージョン `0.1.0` では、テスターが `Active` でもビルドのBeta指定がない状態で「テスト版の有効期限が切れました」と表示されました。`promote` でBetaへ切り替えた後、iPhoneへのインストール成功を確認しています。

### 6. 次のバージョンを配布する

同じアプリを更新するときは、`app.json` の `version` を上げます。例えば `0.1.1` に変更したら、再ビルド・パッケージ作成後、次を実行します。


初回の `create` と、登録済みアプリの更新に使う `upload` を使い分けます。同じバージョン番号を再アップロードすることはできません。[公式のビルド更新手順](https://hub.evenrealities.com/docs/cli/builds)

## 現在の開発状況

### 実装済み

- `waitForEvenAppBridge()` で接続し、入力を受け付けるテキストコンテナと波形用の画像コンテナを作成。
- `onEvenHubEvent()` でシングルタップを受信し、`audioControl(true)` / `audioControl(false)` でマイクを操作。
- `event.audioEvent.audioPcm` の16 kHz・モノラル・符号付き16-bitリトルエンディアンPCMを、32768で割って正規化。
- 録音区間全体のPCM配列と、表示用の直近5秒（80,000サンプル）のリングバッファを個別に保持。
- 288 × 144 pxの画像コンテナ1枚に、各ピクセル列の最小値・最大値を縦線で描画。
- 横軸は左0、右5で固定し、その下の中央に `Time[s]` を表示。0〜5は表示窓内の位置を表し、右端の5が最新サンプルに対応。
- 縦軸は−1〜+1で固定し、プロットの枠を全周に描画。録音開始から5秒未満の未収録部分には波形を描画しない。
- 200 ms間隔（毎秒5回が目安）で画像を更新。同時に送る画像は1件とし、転送中の更新要求はまとめて、次に送れる時点の最新波形を描画。
- 停止タップで録音区間を即座に閉じ、遅れて届くPCMは記録・解析・波形へ追加しない。
- Web Workerで録音全体のFFTを解析し、計算中は停止時の時間波形に画面中央の `Calculating...` を重ねて点滅。
- 576 × 288 pxのFFT画面を288 × 144 pxの画像4枚で表示。旧画面の送信完了を待ってから画面を再構成し、4枚を直列に転送。
- 結果画面からの再録音と、短すぎる録音や解析エラーからの復帰。
- FFT画面の標準メニューからCursor mode / Normal modeを切替。カーソルの1ビン移動、最大位置への復帰、Hz・dBの数値表示。
- 連続操作では入力ごとにカーソル位置を更新し、画像転送は4タイル単位で直列化。転送待ちの描画要求はまとめて最新状態を送信。

### FFTの解析・表示仕様

| 項目 | 仕様 |
| --- | --- |
| 対象 | 停止タップまでの録音全体 |
| フレーム長 | 2,048サンプル |
| オーバーラップ | 75%（ホップ512サンプル） |
| 窓 | 周期的Hann窓。DC除去なし |
| 周波数分解能 | 7.8125 Hz（16 kHz入力） |
| 正規化・平均 | 窓の振幅利得を補正した片側RMSパワーを、ビンごとに算術平均 |
| dB変換 | `10 log10(meanPower / (2e-5)^2)` |
| 周波数範囲 | 0〜3,000 Hz。500 Hz間隔の目盛りと `Frequency[Hz]` ラベル |
| 縦軸 | `Amplitude` ラベルとdB基準の補助表記。表示範囲内の値でオートスケール |
| 下限処理 | −120 dB以下は−120 dBへ打ち切り、その値を最小・最大値の計算から除外 |
| 上下の余白 | 有効な最大dB値と最小dB値の差の10%ずつ |
| 無音時 | 有効値がなければ−120〜−110 dBで表示 |
| 同一値の場合 | 有効値の差が10⁻⁶ dB以下なら、その中心値の上下5 dBで表示 |
| 不足フレーム | 末尾の不完全なフレームは使用せず、全体が2,048サンプル未満なら再録音を案内 |

フレームごとのパワーは `c × abs(FFT(x × w))^2 / sum(w)^2` とし、係数 `c` は通常ビンで2、DC・ナイキストで1です。dB変換はパワーを平均した後に行います。

dB値は正規化PCMに基準値 `2e-5` を適用した値です。実測音圧への校正係数は含めていません。計算時間を引き延ばすための待機時間は設けていません。

### 確認した結果

以下はシミュレーターでの検証結果です。振幅や更新レートの測定値は、入力音や実行環境によって変わります。

| 確認項目 | 結果 |
| --- | --- |
| 最小表示と入力 | `FFT ready` → シングルタップ → `Tap received` を確認。その後、タップの動作を録音開始・停止へ変更済み |
| 内蔵マイクの受信 | 1件3,200バイト（1,600サンプル）、毎秒約10件を受信 |
| 音への反応 | 声・手拍子で最大振幅が約0.1から0.99997へ上がり、その後低下することを確認 |
| 時間波形 | 発声・無音・再発声で、強い音の区間が右側から左側へ移動することを確認 |
| 更新レート | 通常約5回/秒。波形確認時の計測平均は約4.1回/秒で、一時的な低下あり |
| 停止後の固定 | 解析中も録音区間と背景波形が固定。FFT導入前の波形単体検証では、停止後約28秒間画面が一致 |
| 合成FFT | 1 kHz正弦波のピーク位置を確認。ピーク振幅0.5で約84.95 dB、1で約90.97 dB（RMS基準） |
| FFT画面遷移 | 録音停止→時間波形と点滅表示→全画面FFT→再録音を確認。計算中の追加タップは無視し、短すぎる録音からも復帰 |
| カーソル操作 | 標準メニュー、1ビン移動、タップで録音しないこと、ダブルタップで最大位置へ戻ること、長押しとメニューでの復帰を確認 |
| モード切替 | Normal modeへ戻した画像が元の画像と一致。30回の連続スクロール後も最終位置が一致し、Normal modeから再録音できることを確認 |
| 自動テスト | 従来の解析・転送テストに、モード別入力、メニュー、カーソル移動、単位表示、連続操作を追加。34件が成功 |
| ビルド | FFT Workerを含めて `npm run build` が成功 |

シミュレーター0.9.5での検証では、`audioControl(false)` の戻り値が `false` でもPCM受信は停止しました。戻り値はコンソールログに残します。録音区間は停止タップ時点で閉じ、マイク停止処理とFFT解析を並行して進めます。再録音時は前回の停止要求の完了を待ちます。

点滅の確認では、一時的な検証サーバーでWorker応答を1.8秒遅らせて確認しました。この遅延処理はアプリ本体には含まれていません。
