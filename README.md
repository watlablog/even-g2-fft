# even-g2-fft

Even G2のマイクで録音し、平均化したFFT振幅スペクトルを表示するアプリの開発プロジェクトです。TypeScriptとEven Hub Web SDKを使用します。

現在は、録音の開始・停止、直近5秒の時間波形、録音終了後の平均化FFT、Cursor mode、振幅順位を選ぶPeak mode、直近4フレームの平均FFTを更新するRT modeを実装しています。シミュレーターではmacOSの内蔵マイクで検証済みです。G2実機でも初期画面、録音、FFT表示、Peak / RT modeの基本操作まで確認しています。

セットアップ済みの環境で再確認する場合は、[実機でのビルド・起動・動作確認](#実機でのビルド起動動作確認)の手順を順に実行してください。

メガネのメニューから起動するためのインストール手順は、[Beta版の作成・登録・インストール](#beta版の作成登録インストール)にまとめています。

## シミュレーターの起動と手動テスト

ビルド済みの画面を使う場合は、ターミナルを2つ開きます。

### ターミナル1：ビルドとプレビューサーバー

```bash
cd /path/to/even-g2-fft
npm run build
npm run preview -- --port 4173 --strictPort
```

サーバーを起動したままにします。`--strictPort` を指定しているため、4173番ポートが使用中の場合は既存のサーバーを終了してから再実行してください。

### ターミナル2：内蔵マイクを指定して起動

以下は、内蔵マイクのデバイスIDが `coreaudio:BuiltInMicrophoneDevice` の場合のコマンド例です。

```bash
cd /path/to/even-g2-fft
npx evenhub-simulator http://localhost:4173/ --aid "coreaudio:BuiltInMicrophoneDevice"
```

`--aid` の値は `--list-audio-input-devices` の結果に合わせて指定してください。macOSのマイク許可が表示された場合は「許可」を選択します。

### 操作

1. 初期画面に `FFT ready` と `Tap to record` が表示されます。
2. シミュレーターの `Click`（シングルタップ）操作で録音を開始します。
3. 選択したマイクに向かって「話す → 数秒黙る → また話す」と操作し、音の強い区間が右端から左へ移動することを確認します。
4. もう一度シングルタップすると録音区間が閉じ、停止時点の波形に `Calculating...` を重ねて解析します。メッセージは500 msごとに表示／非表示が切り替わり、解析後に全画面FFTへ移ります。計算が速い場合は点滅の切り替わり前に結果が表示されます。
5. 結果画面はNormal modeで表示されます。シングルタップで新しい録音を開始し、前の録音データをリセットします。カーソルを使う場合は、以下のメニュー操作でCursor modeへ切り替えます。
6. 128 ms未満の録音では短すぎる旨を表示します。シングルタップで録音し直せます。計算中と画面切替中のタップは無視します。

録音データはメモリ内に保持します。音声ファイルへの保存は実装していません。

### FFT画面のカーソル操作

FFT結果画面で「タップ→長押し」の標準メニューを開き、`Cursor mode`、`Normal mode`、`Peak mode`、`RT mode`を選びます。シミュレーターではContext Menu操作でも開けます。

| 操作 | Normal mode | Cursor mode |
| --- | --- | --- |
| シングルタップ | 新しい録音を開始 | 何もしない |
| Upスクロール | 何もしない | 低周波側へ移動。同方向の連続入力で自動加速 |
| Downスクロール | 何もしない | 高周波側へ移動。同方向の連続入力で自動加速 |
| ダブルタップ | 何もしない | 目立つ局所ピークのうち、現在位置から周波数が最も近いものへスナップ |
| 長押し | アプリ側での追加処理なし | Normal modeへ戻す |
| メニューのモード選択 | 選んだモードへ切替 | 選んだモードへ切替 |

- 1ビンは7.8125 Hzです。0〜3,000 Hzの端で止まり、反対側には移動しません。
- 同じ方向の入力が800 ms未満の間隔で続くと、最初の2回は1ビン、3回目から4→8→16→32→64ビンへ加速します。7回目以降は最大64ビン＝500 Hzずつ移動します。
- 前のスクロールから800 ms以上空いた場合と、方向を反転した場合は、1回目の1ビン移動に戻ります。目標位置を越えて動き続ける慣性移動は行いません。
- 新しいFFT、モード切替、メニュー開閉、ピークへのスナップ、表示範囲の端への到達で加速を解除します。シングルタップは録音も速度変更も行いません。
- Cursor modeを選ぶたびに、表示範囲内の平均パワーが最大のビンへカーソルを配置します。同率なら低周波側、全無音なら0 Hzを選びます。
- ダブルタップでは、0〜3,000 Hz内でプロミネンスが6 dB以上の局所ピークから、周波数距離が最小のものを選びます。等距離なら振幅が大きい方、それも同じなら低周波側を選びます。全体の最大位置に戻したい場合は、メニューで `Cursor mode` を選び直します。
- 局所ピークは、両側の隣接ビンより高い山です。同じ高さが続く頂点は中央のビン（偶数個なら低周波側の中央）を使います。表示範囲の両端と−120 dB以下は対象外で、ピークがなければ位置を保ちます。平滑化やビン間の補間は行いません。
- プロミネンスは山頂と周囲の谷の高さの差です。山頂から左右へ、それより高い山または表示範囲の端まで調べ、それぞれの側の最低値のうち高い方を基準とします。`山頂dB − max(左側の最低dB, 右側の最低dB)` が6 dB未満の小さな凹凸を除外します。候補がなければカーソルを動かさず、弱い凹凸へ戻る処理は行いません。判定だけを変え、表示波形と振幅値は維持します。[プロミネンスの定義](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.peak_prominences.html)
- 操作中はグラフ下端の小さな三角マーカーで位置を示し、600 ms入力がなければ縦の破線へ戻します。大きな移動は250 msで補間し、4ビン以下の細かな移動は即座に反映します。補間は表示更新に合わせて進め、古い中間フレームを順に再生する処理は行いません。
- 方向反転やダブルタップでは、未表示の目標位置ではなく、最後に表示更新を確認できた位置から操作を行います。補間を中断して微調整・ピーク合わせを反映します。
- グラフ右上の周波数・振幅はネイティブテキストで、小数点以下2桁と単位を表示します。数値は補間途中も表示中の整数FFTビンに対応し、振幅値の補間はしません。打ち切り値は `≤-120.00 dB` と表示します。
- モード切替とカーソル移動ではFFTを再計算せず、元の軸範囲を保持します。Normal modeではカーソルと数値欄を消し、元のグラフを復元します。
- メニュー表示中は背後の画面の入力と新しい画像転送の開始を抑止し、メニューが閉じてから選択したモードを描画します。長押しの解放では録音を開始しません。

加速はスクロールイベントの受信間隔と連続回数で判定します。画像転送を待つ間も入力ごとに目標位置を更新し、次に送れる時点の最新の表示位置を描画します。スワイプの長さや指の速度を直接測定しているわけではありません。

FFT背景をキャッシュし、直前に転送した画像と変わったタイルだけを直列に送ります。マーカー移動は通常1枚、タイル境界をまたぐ場合は2枚、縦線との切替やメニューからの復帰では必要な複数枚を更新します。初期表示は4枚です。数値の更新では画像を再送しません。画像送信中に新しい操作が届いた場合は、送れる時点の最新状態を使います。

### カーソル自動加速の手動確認

1. 録音を終了し、FFT画面のメニューから `Cursor mode` を選びます。
2. 1秒以上間を空けて同じ方向へスクロールし、1ビンずつ微調整できることを確認します。
3. 同じ方向へ間を空けずにスクロールを続け、3回目の入力から移動幅が大きくなることを確認します。
   操作中は小さな三角マーカーになり、大きな移動の途中にも位置が更新されることを確認します。
4. 1秒以上待って次のスクロールを行い、1ビン移動へ戻ることを確認します。
   待っている間にマーカーが縦線へ戻り、数値とカーソル位置が一致することも確認します。
5. 再び加速してから反対方向へ操作し、最初の2入力が1ビンずつになることを確認します。
6. 両端で止まることと、入力を止めた後に動き続けないことを確認します。
7. 任意の大きな山の近くへ移動してダブルタップし、細かな凹凸を飛ばして、近くの目立つ頂点へ合うことを確認します。別の山の近くでも試します。プロミネンス6 dB以上の候補がない場合は、その位置を保ちます。
8. スナップ直後は最初の2入力が1ビンずつになることと、メニューで `Cursor mode` を選び直すと全体の最大位置に戻ることを確認します。

自動加速の操作性向上と、プロミネンスによるピーク選択はG2のプロトタイプモードで確認済みです。Peak / RT modeの基本操作は実機確認済みです。RTの全画面表示、固定縦軸、500 msの表示保持、4フレーム平均、Pause時の上限合わせも実機確認済みです。これらの変更を含むBeta `0.2.0` を配布済みです。EvenアプリのBeta testerから更新できます。プロトタイプモードで試す場合は、最新ビルドのQRを読み取ってください。

### Peak mode

録音またはRT modeの結果画面で、標準メニューから `Peak mode` を選ぶとTop1へ移動します。右上に順位・周波数（Hz）・振幅（dB）を表示し、縦の破線を選択したピークに合わせます。

| 操作 | 動作 |
| --- | --- |
| Down | Top1→Top2→…と振幅順位を進める |
| Up | …→Top2→Top1と戻る |
| ダブルタップ | Top1へ戻る |
| シングルタップ | 何もしない |
| 長押し | 同じFFTのNormal modeへ戻る |

小さな凹凸を含むすべての局所ピークから、振幅順に最大10個を選びます。Cursor modeのプロミネンス6 dB条件は適用しません。同率なら低周波側を優先し、平坦な頂点は中央ビン（偶数個なら低周波側の中央）を使います。表示範囲の両端と−120 dB以下は除外します。候補が10個未満なら実際の個数を表示し、候補なしなら `No peaks` と表示します。

順位の端で止まり、加速・補間・循環は行いません。DownとUpはCursor modeと同じ操作方向ですが、ここでは振幅順位を選ぶため、周波数軸上の移動は左右どちらにもなります。

### RT mode

初期画面またはFFT結果画面の標準メニューで `RT mode` を選ぶと、マイクを開始して全画面FFTを更新します。

| 操作 | 動作 |
| --- | --- |
| 更新中にシングルタップ | マイクと更新を停止し、表示中の平均FFTに縦軸上限を合わせて `RT paused` と表示 |
| 停止中にシングルタップ | マイクを再開し、新しい音声のFFTへ更新 |
| 長押し | マイクを停止し、最後の表示結果を使ってNormal modeへ戻る |
| スクロール・ダブルタップ | 何もしない |

- 16 kHz・正規化PCMの2048点（128 ms）を1フレームとし、重複なしでHann窓を適用します。**常に直近4フレーム（512 ms）の線形RMSパワーをビンごとに平均し、その後dBへ変換**します。dB値や振幅そのものの平均ではありません。周波数分解能は7.8125 Hz、RMSパワーとdB基準は通常録音と共通です。開始・再開直後は集まった1〜3フレームで平均し、4フレームがそろったら直近4フレームだけを使います。512 msの平均化区間と、送信後500 msの表示保持は別の処理です。
- 表示領域は576 × 288 pxの全画面、横軸は0〜3000 Hzのままです。縦軸は、RT開始後に最初に送信を完了した有効なFFTのdB範囲に上下10%の余白を付けて固定します。更新中とメニュー開閉では軸を変えません。Pauseでは、停止直前に表示していた平均FFTの最大dB値に上限を合わせます。下限は維持し、最大dB値と下限の差の10%を上側の余白にします。最大値が下限以下なら下限から10 dBの有効範囲を確保し、完全な無音なら直前の範囲を維持します。再開後はPauseで調整した軸を維持し、RTを終了して新たに開始すると設定し直します。完全な無音では−120〜100 dBを仮表示し、有効なFFTが現れるまで範囲を確定しません。固定範囲を超える波形は枠内で切り取って描画しますが、解析値そのものは変更しません。時間波形は表示しません。
- RTの時間データ・録音全体・長期のFFT履歴は保存しません。PCM組み立て1フレーム、解析中1件、置換可能な待機1フレームに加え、平均化用のパワー配列を最大4フレームだけ保持します。処理遅延でFFTフレームを飛ばした場合は入力フレーム番号で古いパワーを除外し、512 msを超えた過去データを混ぜません。表示用にも最新結果と最後に送信を完了した結果だけを保持し、履歴を蓄積しません。RT開始前のFFTは、結果未取得時の復帰用に保持します。
- 初回の結果がない間は `Waiting for audio...` と表示します。停止・再開時は不完全なPCMと平均化用のパワー履歴を破棄し、停止前後の音を混ぜません。再開直後は新しい結果が届くまで固定結果を表示します。
- 画像は4枚を直列に送り、1回の画面更新を同じFFT結果で構成します。**全タイルと必要なテキストの送信完了後、500 msは次の画像送信を始めず、読み取り時間を確保します。** その間も解析を続け、転送できる時点の最新の平均FFTだけを描画・送信します。転送時間に500 msを加えた更新間隔となり、毎秒一定回数の更新を保証する方式ではありません。古い結果や中間画像は蓄積せず、ページの作り直しも更新ごとには行いません。
- 全画面更新は転送可能な速度で行うため、128 msごとの画面更新は保証しません。公式資料の約800 msは参考値です。SDKの成功応答は画素の表示完了通知ではないため、停止時には全タイルの送信が成功した最後のフレームを採用します。途中まで送った次のフレームがあれば、固定結果を再描画します。[画像転送の仕様](https://hub.evenrealities.com/docs/build/display)
- RTからNormal / Cursor / Peak modeを選ぶ場合もマイクを止め、固定結果とその縦軸範囲を利用します。RT結果が一度も表示されていなければ、長押しまたはNormal modeで開始前のFFTへ戻り、それもなければ初期画面へ戻ります。RT結果の取得前はCursor / Peak modeの選択を無視します。
- メニュー表示中は画像転送の開始を抑止します。更新中なら解析は続けて最新結果を保持し、停止中なら固定結果を保持します。開始・停止・再開の処理中は追加タップを無視し、長押し終了は受け付けます。500 msの表示保持は送信処理を占有しないため、停止・再開・長押しは保持時間の終了を待ちません。RT modeの再選択では停止・再開しません。

#### Peak / RT modeの手動確認

1. 初期画面のメニューからRT modeを開始し、発声や入力音の変化でFFTが変わることを確認します。最初の有効なFFTを表示した後は縦軸の数値が固定され、画像更新の間に静止時間があることも確認します。
2. タップで停止し、下限はそのままで上限が表示中の平均FFTの頂点に合うことを確認します。その後数秒待って波形と軸が動かないこと、もう一度タップすると調整後の軸で更新が再開することを確認します。
3. 長押しでNormal modeへ戻り、固定結果をCursor modeで調べます。
4. Peak modeへ切り替え、Down / Upで順位が1つずつ変わることと、ダブルタップでTop1へ戻ることを確認します。
5. 長押しでNormal modeへ戻り、タップで通常録音を開始・終了できることを確認します。
6. FFT結果画面からRT modeを再開始し、メニューから直接Peak / Cursor modeへ移ってもマイクが停止し、固定結果を操作できることを確認します。

コードを変更した場合は、再度 `npm run build` を実行し、シミュレーターを終了して起動し直してください。プレビューサーバーはビルド済みの `dist/` を配信します。

## 現在の開発状況

### 実装済み

- `waitForEvenAppBridge()` で接続し、入力を受け付けるテキストコンテナと波形用の画像コンテナを作成。
- `onEvenHubEvent()` でシングルタップを受信し、`audioControl(true)` / `audioControl(false)` でマイクを操作。
- `event.audioEvent.audioPcm` の16 kHz・モノラル・符号付き16-bitリトルエンディアンPCMを、32768で割って正規化。
- 録音区間全体のPCM配列と、表示用の直近5秒（80,000サンプル）のリングバッファを個別に保持。
- 288 × 144 pxの画像コンテナ1枚に、各ピクセル列の最小値・最大値を縦線で描画。
- 横軸は左0、右5で固定し、その下の中央に `Time[s]` を表示。0〜5は表示窓内の位置を表し、右端の5が最新サンプルに対応。
- 縦軸は−1〜+1で固定し、プロットの枠を全周に描画。録音開始から5秒未満の未収録部分には波形を描画しない。
- 200 ms間隔（毎秒5回が目安）で画像を更新。同時に送る画像は1件とし、転送中の更新要求はまとめて、次に送れる時点の最新波形を描画。
- 停止タップで録音区間を即座に閉じ、遅れて届くPCMは記録・解析・波形へ追加しない。
- Web Workerで録音全体のFFTを解析し、計算中は停止時の時間波形に画面中央の `Calculating...` を重ねて点滅。
- 576 × 288 pxのFFT画面を288 × 144 pxの画像4枚で表示。初期表示では4枚を直列に転送し、カーソル移動中は変わったタイルだけを送信。
- 結果画面からの再録音と、短すぎる録音や解析エラーからの復帰。
- FFT画面の標準メニューからNormal / Cursor / Peak / RT modeを切替。カーソルの1ビン移動、最近傍ピークへのスナップ、モード再選択での最大位置への復帰、Hz・dBの数値表示。
- カーソルの同方向連続スクロールを3回目から自動加速。最大500 Hz、800 ms以上の間隔や方向反転で1ビンの微調整へ復帰。
- 操作中は軽量マーカーとネイティブ数値表示を使い、600 ms入力がなければ縦線に復帰。大きな移動は250 msで補間し、反転・ピーク合わせは表示位置から行う。
- 連続操作では入力ごとに目標位置を更新し、画像転送を直列化。背景をキャッシュし、転送待ちの描画要求はまとめて最新状態を送信。

- Peak modeで局所ピークを振幅順に最大10個選択。ダブルタップでTop1へ復帰。
- RT modeで重複なしのFFTを解析し、直近4フレーム（512 ms）のパワーを移動平均。タップで停止・再開し、Pause時には上限だけを表示中の平均FFTへ合わせる。長押しで平均結果と軸をNormal modeへ固定。

### 通常録音のFFT解析・表示仕様

| 項目 | 仕様 |
| --- | --- |
| 対象 | 停止タップまでの録音全体 |
| フレーム長 | 2,048サンプル |
| オーバーラップ | 75%（ホップ512サンプル） |
| 窓 | 周期的Hann窓。DC除去なし |
| 周波数分解能 | 7.8125 Hz（16 kHz入力） |
| 正規化・平均 | 窓の振幅利得を補正した片側RMSパワーを、ビンごとに算術平均 |
| dB変換 | `10 log10(meanPower / (2e-5)^2)` |
| 周波数範囲 | 0〜3,000 Hz。500 Hz間隔の目盛りと `Frequency[Hz]` ラベル |
| 縦軸 | `Amplitude` ラベルとdB基準の補助表記。表示範囲内の値でオートスケール |
| 下限処理 | −120 dB以下は−120 dBへ打ち切り、その値を最小・最大値の計算から除外 |
| 上下の余白 | 有効な最大dB値と最小dB値の差の10%ずつ |
| 無音時 | 有効値がなければ−120〜−110 dBで表示 |
| 同一値の場合 | 有効値の差が10⁻⁶ dB以下なら、その中心値の上下5 dBで表示 |
| 不足フレーム | 末尾の不完全なフレームは使用せず、全体が2,048サンプル未満なら再録音を案内 |

フレームごとのパワーは `c × abs(FFT(x × w))^2 / sum(w)^2` とし、係数 `c` は通常ビンで2、DC・ナイキストで1です。dB変換はパワーを平均した後に行います。

dB値は正規化PCMに基準値 `2e-5` を適用した値です。実測音圧への校正係数は含めていません。計算時間を引き延ばすための待機時間は設けていません。

### 確認した結果

以下はシミュレーターでの検証結果です。振幅や更新レートの測定値は、入力音や実行環境によって変わります。

| 確認項目 | 結果 |
| --- | --- |

シミュレーター0.9.5での検証では、`audioControl(false)` の戻り値が `false` でもPCM受信は停止しました。戻り値はコンソールログに残します。録音区間は停止タップ時点で閉じ、マイク停止処理とFFT解析を並行して進めます。再録音時は前回の停止要求の完了を待ちます。
